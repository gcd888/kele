# 可乐 · 重构评估与迁移方案

> 版本：v2.0 ｜ 日期：2026-10-13
>
> 结论先行：kelePro 架构方向正确（Workers + D1 + uni-app），**值得保留其成果但整体迁出 demo 目录**。
> 按本文方案将 kelePro 有价值部分整合进 kele 项目，裁剪冗余，补齐扩展性框架与小程序端，然后删除 `demo/kelePro`。

---

## 1. kelePro 现状评估

### 1.1 做对了的（保留）

| 亮点 | 位置 | 说明 |
|------|------|------|
| Serverless 架构选型 | wrangler.toml | Workers + D1 + Cron 全免费，静态资源随 Worker 托管 |
| 服务端直连第三方 | services/* | 已摆脱浏览器 CORS 依赖，腾讯云函数代理网关可彻底移除 |
| 资源缓存落库 | services/search.ts | 搜索结果 D1 缓存 + 预热 + 过期清理，缓解源不稳定 |
| api_configs 配置表雏形 | db/schema.ts | URL/method/headers/status/priority 已配置化 |
| 通用 API 源思路 | crawlers/lzpan.ts | "从配置表读源并发请求"已具声明式框架雏形 |
| 网盘类型自动识别 | utils/cloud-detector.ts | 按 URL 模式识别 cloud_type，兜底能力强 |
| 榜单驱动预热 | schedules/* | 豆瓣全量 → 热门词预热 → 缓存常新，数据流设计合理 |
| uni-app 双端基础 | manifest.json | h5 + mp-weixin 条件编译配置存在 |

### 1.2 核心缺陷（重构要解决的）

| # | 缺陷 | 后果 | 严重度 |
|---|------|------|--------|
| P1 | **解析器代码耦合**：`parsers.ts` 硬编码，`api_configs.request_type` 只能选内置格式；新返回格式必须改代码重新部署 | "接口易失效→功能不可用"的根因未解决 | ★★★ |
| P2 | **无健康监控/熔断**：源挂了照常扇出，用户只见空结果；站长无感知，故障定位靠人肉 | 源失效不可运营 | ★★★ |
| P3 | **小程序未完成**：mp-weixin appid 占位、无白名单域名方案（workers.dev 不可入白名单）、无小程序交互适配 | 双端目标未达成 | ★★★ |
| P4 | **系统过重**：注册/登录/VIP 等级/广告四套体系，免费个人项目维护成本高、审核风险大 | 复杂度与收益倒挂 | ★★ |
| P5 | **安全缺陷**：`/api/debug/init`、`/api/debug/cron-trigger` 无鉴权，任何人可重置数据库/触发任务 | 数据被清空风险 | ★★★ |
| P6 | **CPU 红线未评估**：xiaozi/zhuiju 正则解析整页 HTML，免费版 10ms CPU/次有超限风险 | 线上随机失败 | ★★ |
| P7 | **后台能力弱**：admin 后台只有配置/公告 CRUD，无连通性测试、无健康度、无声明式字段映射 | 运维不可自助 | ★★ |
| P8 | **项目位置混乱**：kelePro + 原静态版 + 三个示例项目全堆在 demo/ 下，文档/代码/资料混杂 | 不可维护 | ★★ |

### 1.3 "接口易失效"根因链（重构前后对照）

```
根因链：第三方源无 SLA → 单源故障 = 功能缺口 → 无健康感知（照常扇出） → 无降级（空结果） → 无快速替换手段（改代码发版）
                     ↑ 原系统卡在这里
新方案：L0 声明式接入（5 分钟换源） + 健康度/熔断（分钟级感知） + 缓存兜底（stale 可用） + 预热常新 → 单源失效对用户无感
```

## 2. 整合决策：kelePro → kele

## 3. 实施步骤

| 阶段 | 动作 | 验收标准 |
|------|------|----------|
| S1 骨架 | 建 kele/{apps/web,worker,docs}；迁移 utils/db/crawlers；wrangler 本地跑通 /api/health | `wrangler dev` curl 通过 |
| S2 源框架 | L0 适配器 + L1 注册表（迁移 4 解析器）+ L2 爬虫迁移；搜索编排（扇出/去重/缓存/降级） | curl `/api/search?kw=流浪地球` 出结果；手动停一个源仍出结果 |
| S3 熔断 | fail_count/disabled_until + 探测 Cron + 健康度 API | 连续 3 次失败自动禁用，30 分钟后自动恢复 |
| S4 H5 | 首页/搜索/详情/声明页迁移 + 管理后台四页 | 浏览器全流程可用 |
| S5 后台 | 源 CRUD + 声明式表单 + 测试连通 + 健康度页 | **后台添加一个真实新源并搜索成功，全程未改代码** |
| S6 小程序 | mp-weixin 构建、条件编译、本地收藏/历史；备案域名绑定 + 白名单 | 开发者工具真机预览通过 |
| S7 收尾 | D1 迁移应用、Cron 生效验证、CI 部署、归档并删除 demo/kelePro | 线上 H5 可访问、Cron 日志正常 |

## 4. 测试要点

1. **源框架回归**：每个内置解析器用功能文档 §B 的契约样本（含 searchApi2 纯文本）做单测。
2. **熔断演练**：本地将某源 URL 改为无效地址，观察 3 次失败 → 熔断 → 30 分钟探测恢复。
3. **额度演练**：模拟冷搜索高峰，确认 D1 日写入 < 10 万、KV 日写 < 1,000、单请求子请求 < 50。
4. **小程序**：真机测试复制分步交互、审核模式开关前后差异。
5. **安全**：未带 JWT 访问 `/api/admin/*` 全部 401；`/api/debug/init` 已不存在。

## 5. 遗留风险提示

- 备案域名是小程序上线的前置条件，建议 S4 期间并行办理（周期最长不可控）。
- 豆瓣/网盘检测接口可能随时变更：均已隔离在独立文件，失败不阻塞搜索主链路。
- 若未来 DAU 增长触发免费额度瓶颈，优先开"仅缓存模式"限流，其次考虑 Workers 付费档（$5/月），架构无需变更。
