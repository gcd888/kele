# 可乐 · 架构设计文档

> 版本：v2.0 ｜ 日期：2026-10-13
>
> 目标：kele 单一项目 = uni-app 双端前端（H5 + 微信小程序） + Cloudflare Workers 后端（免费方案），
> 核心设计围绕**源强扩展性**：新接口配置即接入，源失效自动熔断，功能不因单个第三方源死掉而不可用。

---

## 1. 总体架构

```
                    ┌──────────────────────┐        ┌──────────────────────┐
                    │  微信小程序 (mp-weixin) │        │   网页 H5 (响应式)      │
                    │  uni-app 一套代码       │        │   uni-app 构建+ASSETS   │
                    └──────────┬───────────┘        └──────────┬───────────┘
                               │  HTTPS（备案域名，小程序白名单）   │
                               ▼                               ▼
                    ┌─────────────────────────────────────────────────┐
                    │        Cloudflare Worker（唯一后端入口）            │
                    │  /api/*  路由层 → 服务层 → 源适配器框架（核心）        │
                    │  JWT 管理鉴权 / 限流 / CORS                        │
                    ├─────────────────────────────────────────────────┤
                    │  绑定: D1(主存储)  KV(低频状态)  Cron(4个定时任务)     │
                    └───────┬─────────────────────────────────────────┘
                            │ 服务端 fetch（替代原腾讯云函数代理网关）
            ┌───────────────┼────────────────┬──────────────────┐
            ▼               ▼                ▼                  ▼
      第三方搜索 API     HTML 爬虫源       网盘失效检测接口      豆瓣榜单 API
      (iyuns/eeeob…)  (盘小子/追剧吧)    (夸克/阿里/百度)      (rexxar)
```

要点：

1. **一个 Worker 承载全部**：API + H5 静态资源（Workers Assets），免费额度内最省。
2. **服务端直连第三方**：Worker 间请求无 CORS 问题，原静态版的腾讯云函数代理网关整体移除。
3. **数据不入站**：仅索引分享链接与元信息，资源本身不存储（合规基线）。

## 2. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 前端框架 | uni-app（Vue3 + TS + Vite） | 一套代码 → H5 + mp-weixin，kelePro 已验证可行 |
| UI | 自研轻组件 + 原生 CSS 变量主题 | 小程序包体积与审核友好，避免重型 UI 库 |
| 后端 | Cloudflare Workers（TypeScript） | 免费额度满足个人站；Cron/D1/KV 一站式 |
| 数据库 | Cloudflare D1（SQLite） | 结构化资源/配置存储，10 万行/天写入够用 |
| KV | 低频状态（源健康度、配置快照） | **注意免费版 KV 写 1,000/天，搜索缓存绝不走 KV** |
| 部署 | wrangler + GitHub Actions | 沿用 kelePro 的两条 workflow |
| 管理后台 | uni-app H5 内 `/admin` 路由（仅桌面样式） | 复用一套代码，无需独立项目 |

## 3. 核心设计：源适配器框架（扩展性方案）

### 3.1 问题定义

第三方搜索源的三种死法：**域名停服**、**返回结构变更**、**风控封禁**。
原系统（kelePro）的解析器硬编码在 `parsers.ts` + `api_configs.request_type` 标识，新格式 = 改代码 = 重新部署。

### 3.2 三级接入体系

```
L0 声明式配置（0 代码，0 部署）—— 覆盖 80% REST API 源
   后台表单：URL 模板 + 方法 + 请求头/体 + 结果路径 + 字段映射 → 存 D1 → 立即生效
L1 内置解析器（1 个文件 + 1 行注册）
   复杂格式（如 searchApi2 的纯文本正则解析）写成解析器函数，注册进 REGISTRY
L2 HTML 爬虫适配器（1 个文件 + 1 行注册）
   网页爬取型源（盘小子/追剧吧），HTMLRewriter/正则轻量解析
```

### 3.3 SourceAdapter 接口

```ts
// 每个源（无论哪一级）运行时都被归一为同一个适配器对象
interface SourceAdapter {
  id: string;                    // api_configs.id
  name: string;
  priority: number;              // 大者优先；扇出时按优先级截断
  timeoutMs: number;             // 默认 3000
  fetch(kw: string, page: number): Promise<Resource[]>;  // 归一化输出
}
```

- **L0 构建**（DeclarativeAdapter）：由 D1 配置行构造，运行时解释执行。
- **L1/L2 构建**：`PARSERS: Record<string, ParserFn>` 注册表，`api_configs.parser` 字段命中注册表即用。

### 3.4 L0 声明式配置 schema（api_configs 表升级）

```sql
ALTER TABLE api_configs ADD COLUMN result_paths TEXT;   -- JSON数组，如 ["data.merged_by_type.quark"]
ALTER TABLE api_configs ADD COLUMN field_map   TEXT;    -- JSON，如 {"title":"name","url":"url","passcode":"pwd","cloud_type":"'quark'"}
ALTER TABLE api_configs ADD COLUMN body_template TEXT;  -- POST 体模板，{kw}/{page} 占位
ALTER TABLE api_configs ADD COLUMN headers       TEXT;  -- 自定义请求头 JSON
ALTER TABLE api_configs ADD COLUMN timeout_ms    INTEGER DEFAULT 3000;
ALTER TABLE api_configs ADD COLUMN source_type   TEXT DEFAULT 'api';  -- api|html
ALTER TABLE api_configs ADD COLUMN enabled       INTEGER DEFAULT 1;
ALTER TABLE api_configs ADD COLUMN fail_count    INTEGER DEFAULT 0;   -- 连续失败计数（熔断依据）
ALTER TABLE api_configs ADD COLUMN disabled_until TEXT;              -- 熔断截止时间
```

字段映射求值规则（实现极简，~40 行）：

- 值形如 `'quark'`（带引号）→ 字面量常量；
- 否则按 `.` 分隔取 JSON 路径（`data.list[*].name` 支持 `[*]` 展开为多条）；
- 提取码用正则后处理：`/(?:提取码|密码|pwd)[:：\s]*([a-zA-Z0-9]{4})/`。

### 3.5 流式搜索编排（SSE，2026-10 决策）

> 决策：通道用 **SSE**（H5 `EventSource` / 小程序 `wx.request enableChunked`），
> 时序用 **先推后校验**：源返回立即推结果（"检测中"态），有效性校验并行完成一批推一批。

```
GET /api/search/stream?kw=    (text/event-stream)

1. 归一化关键词 → 查 D1 缓存（updated_at > now-2h）
   ├─ 命中：一次性推完缓存条目（带最终 validity）→ done（快路径，0 子请求扇出）
   └─ 未命中：
2. emit meta（searchId + 参与源列表）
3. 取 enabled 且未熔断的源，按 priority 截取前 10 个，Promise.allSettled 并行扇出
   （AbortController 单源超时；客户端断开 = abort 全部，节省额度）
4. 每源完成：归一化 → 按 url 全局去重 → cloud-detector 兜底识别
   → emit source_result（条目 validity=checking）
   → 并行发起该源校验（限额见下），完成一批 emit validity 批次事件
5. 每源 emit source_done（耗时/成败）
6. 全部结束：emit done（汇总）；D1 批量落库 + search_logs + 健康度走 ctx.waitUntil 异步
7. 全源失败 → 降级读 D1 旧缓存（stale 标记）推完 → done
```

SSE 事件协议：

| 事件 | data 载荷 |
|------|-----------|
| `meta` | `{searchId, kw, sources:[{id,name}], cached:boolean}` |
| `source_result` | `{sourceId, items: Resource[]}`（validity 均为 `checking`） |
| `validity` | `{sourceId, results:[{url, validity:'valid'\|'invalid'}]}`（批量） |
| `source_done` | `{sourceId, ok, count, tookMs, error?}` |
| `done` | `{total, cached, stale, tookMs}` |
| `error` | `{sourceId?, message}`（流级错误，之后仍会 done） |

**客户端双桶渲染（失效自动沉底）**：SSE 流只追加不可重写，排序在客户端完成——
`source_result` 条目进"有效区"尾部（灰标检测中）；`validity=invalid` 时该条目从有效区移入"失效区"尾部，`valid` 转绿不移动。有效区永远在前、失效区永远沉底，条目仅移动一次不跳动。

**校验子请求预算**（免费版 50/请求）：10 源扇出 + 每源仅前 3 条主动校验 = 40 ≤ 50；
其余条目 `checking` 态，靠 ① D1 有效性缓存命中、② 用户点"检测"/复制时单条查（`/api/resource/check`）、③ 报失效累计触发。

REST 兜底：保留 `GET /api/search`（一次性返回，同编排逻辑聚合后返回），用于不支持流的环境与 SEO/分享预览。

### 3.6 健康度与熔断

```
每次源调用后：
  成功 → fail_count=0, KV 写 source_health:{id} = {ok:1,lat:xx,ts}
  失败 → fail_count+1（写 D1 api_configs）
         fail_count ≥ 3 → enabled=0, disabled_until=now+30min（熔断）
Cron 探测（每小时，复用 debug cron-trigger 改造）：
  对 disabled_until 过期的源发 1 次 1 词测试请求 → 成功则 enabled=1
KV 写入预算：健康度写 = 源数 × 调用批次，实际每源每关键词 1 次 ≪ 1000/天；超预算时静默跳过
```

### 3.7 失效检测器（同样插件化）

```ts
interface ValidityChecker { cloud_type: string; check(url: string): Promise<'valid'|'invalid'|'unknown'> }
```

- 内置：quark（sharepage/token 接口）、aliyun（get_share_by_anonymous）、baidu（HTML 嗅探）；其他类型恒 `unknown`。
- Worker 服务端直连（无网关）；检测结果写 resources.is_valid，缓存 24h（重复检测免请求）。
- 用户"报失效"：`resource_reports` 计数 ≥ 3 直接置 invalid，不再发检测请求（省子请求）。

## 6. Cloudflare 免费额度预算（按日估算）

| 项 | 估算 | 上限 | 余量 |
|----|------|------|------|
| Workers 请求 | 页面+API ≈ 5k（1k DAU 假设） | 100k | 充足 |
| 子请求 | 搜索扇出 10 + 检测 15 + 爬虫翻页 ≈ 30/次冷搜索 | 50/次 | 需守恒（缓存命中为 0） |
| D1 读 | 缓存查询+列表 ≈ 50k | 5M | 充足 |
| D1 写 | 冷搜索 30 条/次 × 300 次冷搜索 + 日志 ≈ 15k | 100k | 充足；超限自动只写热门词 |
| KV 写 | 健康度 ≈ 100 | 1,000 | 安全 |
| Cron | 4 条规则（douban/prefetch/cleanup/probe） | 免费可用 | — |

限流：`每 IP 20 次搜索/分钟`（沿用 rate-limit.ts），超限返回 429；`/admin` 全量 JWT。

## 7. 小程序适配设计

| 事项 | 方案 |
|------|------|
| 域名 | 自有备案域名绑定 Worker Custom Domain；`request 合法域名` 填 `https://api.你的域名` |
| 构建条件编译 | `#ifdef MP-WEIXIN`：复制分步 toast、无外链、导航用 copy 提示；H5：`window.open` |
| 审核 | 审核模式开关（后端下发）隐藏"在线影视"；声明页常驻；类目建议"工具-效率" |
| 降级 | 无备案域名期间仅发 H5；小程序代码就绪待提审 |
| 登录态 | 无用户体系，收藏/历史全本地（wx.setStorage） |

## 8. 部署与 CI

```

cd worker && npx wrangler d1 migrations apply kele-db --remote
npx wrangler deploy          # assets 指向 ../apps/web/dist/build/h5
npx wrangler secret put ADMIN_PASSWORD JWT_SECRET

# 小程序
```

首次初始化：`POST /api/admin/init`（首次且无管理员时允许，创建后失效）替代 kelePro 无鉴权的 `/api/debug/init`。

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| 全部源同时失效 | D1 历史缓存兜底（stale 标记）+ 预热任务保持热门词常新 |
| Workers CPU 超限（爬虫解析） | L2 爬虫只解析前 2 页、正则精简、命中即停；必要时拆 Cron 独立跑 |
| 网盘检测接口加风控 | 检测器同样走 api_configs 式可配置（FR-36），失效不影响搜索主链路 |
| 小程序审核被拒 | 审核模式 + 声明页；被拒后 H5 保底入口不变 |
| D1 写入超免费额度 | 写入白名单：仅热门词与去重后的新 URL 落库，普通词只透传不缓存 |
| 豆瓣接口变更 | douban 爬虫独立文件 + 失败不影响搜索；榜单空时前端隐藏区块 |
